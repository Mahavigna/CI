You already understand the core training loop: calculate prediction, calculate error, backpropagate gradients, and update weights. Adam changes only the final parameter-update rule. MSE or Huber still determines what error is minimized, and backpropagation still calculates the gradients.

1. MSE, backpropagation, SGD, and Adam are different jobs

These concepts fit together as follows:

Inputs
  |
Forward propagation
  |
Prediction
  |
MSE or Huber loss
  |
Backpropagation
  |
Gradients for every weight and bias
  |
SGD or Adam optimizer
  |
Updated weights and biases


Their responsibilities are:

Component	ResponsibilityMSE	Measures squared prediction error
Huber	Measures error with reduced sensitivity to large residuals
Backpropagation	Calculates how each parameter affected the error
SGD	Updates each parameter directly from the current gradient
Adam	Updates each parameter using gradient history and squared-gradient history
OpenCL	Executes the calculations in parallel on the GPU

Adam does not replace MSE, Huber, or backpropagation. Adam replaces this simple update:

parameter -= learning_rate * gradient;

2. Standard SGD update

For parameter θ\theta, such as one weight or bias, ordinary mini-batch SGD is:

θt=θt−1−ηgt\theta_t = \theta_{t-1} - \eta g_t

Where:

θt\theta_t is the updated weight
η\eta is the learning rate
gtg_t is the current mini-batch gradient
tt is the update step

Your original GPU update was approximately:

gradient = gradients[index] / sample_count;
parameter -= learning_rate * gradient;


Every parameter uses the same learning rate.

Example

Suppose:

parameter = 0.50
learning rate = 0.001
gradient = 20.0


SGD performs:

new parameter = 0.50 - 0.001 * 20
              = 0.48


If the next batch produces a gradient of -18:

new parameter = 0.48 - 0.001 * -18
              = 0.498


The parameter oscillates because SGD reacts directly to every batch.

That resembles the behavior in your earlier run where the full-dataset MSE improved quickly and then steadily worsened.

3. What Adam adds

Adam maintains two additional numbers for every parameter:

First moment mm: a moving average of gradients
Second moment vv: a moving average of squared gradients

The name Adam comes from Adaptive Moment Estimation.

For every weight and bias, Adam stores:

parameter
first moment m
second moment v


Your model contains:

6,560 weights
161 biases
6,721 total parameters


Therefore, Adam adds:

6,721 first-moment floats
6,721 second-moment floats


At four bytes per float:

6,721 x 2 x 4 = 53,768 bytes


Only about 52.5 KiB is needed for the Adam state.

4. Adam mathematics

For the current mini-batch gradient gtg_t:

Step A: First moment
mt=β1mt−1+(1−β1)gtm_t = \beta_1m_{t-1} + (1-\beta_1)g_t

Your code uses:

beta1 = 0.9f;


Therefore:

mt=0.9mt−1+0.1gtm_t = 0.9m_{t-1} + 0.1g_t

This is similar to momentum. It smooths the update direction.

If gradients consistently point positive, mm becomes positive. If one batch suddenly produces a negative gradient, the historical positive direction prevents an immediate full reversal.

Step B: Second moment
vt=β2vt−1+(1−β2)gt2v_t = \beta_2v_{t-1} + (1-\beta_2)g_t^2

Your code uses:

beta2 = 0.999f;


Therefore:

vt=0.999vt−1+0.001gt2v_t = 0.999v_{t-1} + 0.001g_t^2

This tracks the recent magnitude of the gradient for that specific parameter.

A parameter with consistently large gradients develops a large vv, reducing its effective update. A parameter with small gradients develops a smaller vv, allowing relatively larger movement.

Step C: Bias correction

Both moment buffers start at zero:

m0 = 0
v0 = 0


During early steps, the moving averages are artificially close to zero. Adam corrects that startup bias:

m^t=mt1−β1t\hat m_t = \frac{m_t}{1-\beta_1^t} v^t=vt1−β2t\hat v_t = \frac{v_t}{1-\beta_2^t}
Step D: Parameter update
θt=θt−1−ηm^tv^t+ϵ\theta_t = \theta_{t-1} - \eta \frac{\hat m_t} {\sqrt{\hat v_t}+\epsilon}

Your epsilon is:

epsilon = 1.0e-8f;


Epsilon prevents division by zero and limits numerical instability when vv is extremely small.

5. Why your code uses a corrected alpha

Your host code calculates:

cl_float alpha = learning_rate * sqrtf(1.0f - powf(adam_beta2, (float)adam_step)) / (1.0f - powf(adam_beta1, (float)adam_step));


This combines the two bias-correction divisions into one corrected learning-rate factor.

Starting with:

θt=θt−1−ηmt/(1−β1t)vt/(1−β2t)+ϵ\theta_t = \theta_{t-1} - \eta \frac{m_t/(1-\beta_1^t)} {\sqrt{v_t/(1-\beta_2^t)}+\epsilon}

Ignoring the extremely small epsilon placement difference, this can be rearranged into:

αt=η1−β2t1−β1t\alpha_t = \eta \frac{\sqrt{1-\beta_2^t}} {1-\beta_1^t}

Then:

θt=θt−1−αtmtvt+ϵ\theta_t = \theta_{t-1} - \alpha_t \frac{m_t} {\sqrt{v_t}+\epsilon}

That is what your implementation performs.

6. Exact mapping from the math to the GPU kernel

Your embedded kernel is condensed:

__kernel void fn_adam_apply(
    __global float *p,
    __global const float *g,
    __global float *m,
    __global float *v,
    uint n,
    uint o,
    uint batch,
    float alpha,
    float b1,
    float b2,
    float eps)


The arguments mean:

Kernel argument	Meaningp	Weights or biases being updated
g	Gradients produced by backpropagation
m	First-moment buffer
v	Second-moment buffer
n	Number of parameters in this layer
o	Parameter offset for this layer
batch	Number of samples in the current mini-batch
alpha	Bias-corrected learning rate
b1	Adam beta1, 0.9
b2	Adam beta2, 0.999
eps	Numerical epsilon, 1e-8
One GPU work-item per parameter
uint x = get_global_id(0);
if (x >= n) return;


Each OpenCL work-item updates exactly one weight or bias.

If a layer has 4,096 weights, the kernel launches approximately 4,096 work-items.

Find the absolute parameter index
size_t i = (size_t)o + x;


The network stores every layer’s parameters in contiguous global arrays. o is the layer’s starting offset and x is the parameter inside that layer.

Convert summed batch gradient to mean gradient
float q = g[i] / (float)batch;


Mathematically:

q=1B∑s=1Bgsq = \frac{1}{B}\sum_{s=1}^{B}g_s

Where BB is the current batch size.

Your gradient kernels sum contributions across the batch. Adam should operate on the mean batch gradient, so the division happens here.

Update first moment
float a = fma(1.0f - b1, q, b1 * m[i]);


fma(x, y, z) calculates:

xy+zxy+z

So this line means:

a = (1.0f - b1) * q + b1 * m[i];


Mathematically:

mt=(1−β1)gt+β1mt−1m_t = (1-\beta_1)g_t+\beta_1m_{t-1}

The order is reversed from the written formula, but addition is commutative.

Update second moment
float z = fma(1.0f - b2, q * q, b2 * v[i]);


Equivalent expanded code:

z = (1.0f - b2) * q * q + b2 * v[i];


Mathematically:

vt=(1−β2)gt2+β2vt−1v_t = (1-\beta_2)g_t^2+\beta_2v_{t-1}
Store the updated history
m[i] = a;
v[i] = z;


These buffers remain on the GPU for the next mini-batch.

Update parameter
p[i] -= alpha * a / (sqrt(z) + eps);


Mathematically:

θt=θt−1−αtmtvt+ϵ\theta_t = \theta_{t-1} - \alpha_t \frac{m_t}{\sqrt{v_t}+\epsilon}

This is the actual Adam parameter update.

7. Why Adam worked better in your model

Your network contains different kinds of parameters:

early-layer weights receiving fuzzy rule activations;
deeper ReLU weights;
output-layer weights;
biases;
parameters active in many samples;
parameters active only in particular fuzzy regions.

Their gradients can have very different scales.

SGD applies:

same learning rate x raw gradient


Adam applies approximately:

smoothed direction / recent gradient magnitude


This gives each parameter an adaptive effective step size.

For your Sugeno mapping:

some rules fire over large regions;
some rule combinations occur around boundaries;
ReLU neurons can be active for only part of the input space;
the linear output sees much larger direct errors than early hidden layers.

Adam helps prevent the large-gradient parameters from dominating everything while allowing smaller consistent gradients to keep moving.

12. MSE and Huber in your two-stage training
Stage 1: MSE

MSE is:

MSE=1N∑i=1N(y^i−yi)2\text{MSE} = \frac{1}{N} \sum_{i=1}^{N} (\hat y_i-y_i)^2

Large errors are squared, so they receive strong attention.

Example:

Error	Absolute error	Squared error2	2	4
10	10	100
30	30	900

This makes MSE effective for coarse learning but sensitive to difficult regions and outliers.

Stage 2: Huber

Huber is quadratic near zero and approximately linear for large errors.

Conceptually:

Lδ(e)={12e2,∣e∣≤δδ(∣e∣−12δ),∣e∣>δL_\delta(e)= \begin{cases} \frac{1}{2}e^2, & |e|\le\delta \\ \delta(|e|-\frac{1}{2}\delta), & |e|>\delta \end{cases}

Your implementation uses:

huber_delta = 10.0f;


So errors within the threshold behave approximately like MSE, while larger errors have bounded gradient behavior.

This helps refine the fit without letting a small number of large errors dominate every update.

13. Why moments reset between MSE and Huber

Every call performs:

fuzzy_neuron_adam_zero(network);


Therefore:

MSE stage:
    m = 0
    v = 0
    step = 0

Huber stage:
    m = 0 again
    v = 0 again
    step = 0 again


The weights are retained between stages, but optimizer history is reset.

That is reasonable because the objective changes from MSE to Huber. Gradient magnitudes and behavior change, so stale MSE moment history might distort the start of Huber refinement.

However, Continue existing model also starts with new Adam moments. The saved CSV contains weights and biases, not optimizer state.

16. He and Xavier initialization

Your hidden layers use ReLU, so the initialization uses:

sqrtf(6.0f / source_count)


This is a uniform form of He initialization.

For the first layer:

source count = 6
sqrt(6 / 6) = 1


So weights are initialized in approximately:

[-1, +1]


For a 64-input ReLU layer:

sqrt(6 / 64) = 0.306186


The linear output uses Xavier:

sqrtf(6.0f / (source_count + destination_count))


For 32 -> 1:

sqrt(6 / 33) = 0.426401


These initializations try to keep activations and gradients from immediately shrinking to zero or exploding.

Your batches are processed sequentially:

Therefore, it can rise even though the latest batches lowered their own local error.

19. The simplest mental model

Think of SGD as:

Move in the direction of the current batch gradient.


Think of Adam as:

Move in the recent consistent direction,
but reduce movement for parameters whose gradients are repeatedly large,
and increase relative movement for parameters whose gradients remain small.


Or in your fuzzy-neuron context:

MSE or Huber says how wrong the output is.

Backpropagation says which weights caused that error.

Adam decides how aggressively each individual weight should change,
using the current gradient and its previous gradient history.
